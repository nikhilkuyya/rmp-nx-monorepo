# Master Overview: Invoice Agent Eval Learning Plan

## Purpose

This plan is for self-learning.

I am building the project myself to understand:

- agent loops
- tool calling
- mock APIs
- evaluation design
- debugging and observability

AI is only a support tool for:

- research suggestions
- concept clarification
- quiz-style learning
- autocomplete

---

## Main Goal

Use a small terminal-based invoice sandbox to learn:

- single-turn evals
- multi-turn evals
- tool-order validation
- semantic judging
- observability and tracing

This is not about building a full invoice product.

---

## Weekly Structure

### Week 1
Foundations, mock data, project setup, eval basics

### Week 2
Single-turn evals: golden, negative, ambiguous

### Week 3
Agent loop basics: state, toolCallIds, safety nets

### Week 4
Runtime visibility and multi-turn evaluation

### Week 5
Judge-based evaluation and observability

### Week 6
Practice, deepening, research, and review

---

## Success Criteria

By the end of this plan, I should have:

- a small terminal-based invoice sandbox
- deterministic mock APIs
- typed tools with `Zod`
- single-turn evals
- multi-turn evals
- tool-order checks
- judge-based scoring
- basic tracing
- stronger understanding of how to improve an agent using evidence

---

## Reminder

The goal is not speed.

The goal is to:

- read carefully
- build deliberately
- test clearly
- observe failures
- improve step by step
